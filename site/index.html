LLM Training, In Reverse

Most training tutorials start from a gradient and build up, and you reach the part where the model talks back hours later. This course runs the tape backwards. We start from a finished chat model, undo its training one stage at a time back to a single weight update, and then rebuild the whole pipeline ourselves: a tokenizer, a model pretrained from scratch, and a chat model of our own.

The pipeline, read right to left

random weights→ pretraining 05, 11→ base model→ SFT 03→ preferences 04→ chat model

Every stage runs the same loop: predict the next token, measure how wrong you were, nudge every weight a little. Only the data and what gets graded change. Part 1 rewinds this pipeline on a real model. Part 2 opens up a single step of that loop. Part 3 builds the pipeline again from zero.

How to use this page

Each lesson matches a script in lessons/. Run it, and it saves its numbers; python site/build_data.py then puts them here. Nothing on this page is hand-typed, so if your run came out differently, the page shows your result.

Predict before you look. Training is full of surprises, and the surprises are the lesson.

What you need

A laptop. Part 1 and 2 run in a few minutes each on a CPU or an Apple Silicon / CUDA GPU. Part 3's pretraining run takes about 10 minutes on an M4 Pro or a modest NVIDIA card. If you've done Transformers, Inside Out, you already know the model; if not, nothing here depends on it.

Lesson 01 · lessons/01_two_models.py

Two models, one body

A base model and its chat version: what is actually different?

SmolLM2-135M is a base model: it read trillions of tokens of web text, books and code, and learned to continue documents. SmolLM2-135M-Instruct is the same model after a few more rounds of training that turned it into an assistant. Same architecture, same 134.5 million parameters, same tokenizer. Only the numbers inside the weights differ.

So the best way to see what that extra training did is to ask both models the same thing, two ways: as plain text, and wrapped in the chat template the instruct model was trained on.

Four ways to ask one question

greedy decoding, 40 tokens

Empty means the model's first token was <|im_end|>: it ended its turn without writing anything.

Three things stand out. The base model answers plain questions like a document would: sometimes with an answer, sometimes by writing the next question on the worksheet. The instruct model says nothing to a plain question. And inside the template, the instruct model answers properly while the base model falls apart.

Why does the instruct model stay silent? Because it has only ever seen questions inside a template. To it, a bare question looks like a finished message, so the most likely next token is "end of turn":

Instruct, after a plain question

next-token probabilities

What the model actually reads

A "chat" is one string. Special tokens mark where each turn starts and ends. These tokens already exist in the base vocabulary, and the base model's config is identical apart from their ids.

Takeaways

  • Base and chat models share an architecture; post-training changes only weights.
  • The chat template is just text with special tokens. A chat model depends on it; the base model never learned it.
  • Post-training taught a format (the template) and a role (answer, then stop). Lesson 02 asks: what else did it change?

Lesson 02 · lessons/02_what_changed.py

What did post-training change?

We have both sets of weights. Subtract them: how big is the edit, where is it, and what did it cost?

Call the difference Δ = Winstruct − Wbase. For each weight matrix, compare the size of the change with the size of the matrix. The size here is just the square root of the sum of all squared numbers.

How much each matrix changed

Rows: the nine kinds of weight in each of the 30 layers. Columns: layers. Darker means a bigger relative change. Hover for the value.

The edit touches every layer, and it is strongest at the very first layer, where tokens are first read in. Is a 9% change big? That depends on its direction. To check, add a random change of exactly the same size to the base model, and compare the result with the real one. Perplexity on a paragraph of encyclopedia text tells us whether the model still "knows" ordinary text (lower is better).

Same size, different direction

perplexity on encyclopedia text

The trained edit leaves the knowledge in place and adds a new behaviour. A random edit of the same size nearly doubles perplexity and doesn't chat.

Dial in the edit

W = Wbase + α·Δ

"What is the capital of France?" in the chat template. α = 0 is the base model, α = 1 is instruct, beyond 1 overshoots.

A small fraction of the edit already flips the model from lost to answering. So what exactly is different in the answers? Let the instruct model write a reply, then ask the base model, token by token: what rank would you have given this token?

The instruct model's reply, coloured by the base model's opinion

hover a token for its rank
rank 0 base agrees 1–2 3–9 ≥ 10 base would not have written this

Takeaways

  • Post-training is a small edit (about 9% of the weights' size), aimed very precisely. A random edit of the same size only damages the model.
  • Knowledge survives: perplexity on ordinary text hardly moves.
  • About half of the chat model's tokens are the base model's top choice anyway. The changed ones are mostly the first word, formatting and tone. This is the superficial alignment hypothesis (LIMA, URIAL, 2023).

Lesson 03 · lessons/03_sft.py

Do SFT yourself

How much data and time does it take to turn a base model into an assistant?

Supervised fine-tuning is ordinary next-token training with two changes. The data is conversations in the chat template, and only the assistant's tokens are graded. Everything else gets the label -100, which tells PyTorch's loss to skip it. That's all loss masking is.

Which tokens get graded?

graded the model is trained to predict thisignored label = −100

The whole training loop fits on one screen. Take a batch of conversations, compute the loss on the graded tokens, call backward() to find which way each weight should move, and take a small step. Lessons 07–09 open up each of those three lines.

for step in range(STEPS):
    x, y, att = pad_batch(next_batch(), device)
    logits = model(x, attention_mask=att).logits
    loss = F.cross_entropy(logits[:, :-1].flatten(0, 1),   # 1. how wrong are we?
                           y[:, 1:].flatten(), ignore_index=-100)
    loss.backward()                      # 2. which way should each weight move?
    opt.step(); opt.zero_grad()          # 3. move them a little

What masking did

test loss, before → after

All the training signal went to the assistant's side. The model learned to answer users, not to imitate them.

A warning about test sets

On this test set, our model beats SmolLM2-Instruct, which was trained on about a million varied conversations. Ours specialised on everyday chit-chat; theirs didn't. A low loss on your own test set only tells you about data like your test set.

Takeaways

  • SFT is next-token prediction on conversations, with the loss masked to the assistant's tokens.
  • A few thousand examples and two minutes are enough to teach the format and the role, because the knowledge was already there.
  • SFT copies the style of its data. To teach a model to prefer one answer over another without writing the answers yourself, you need lesson 04.
